TIL: Spikes

October 24, 2026

Recently, I learned about spikes for software engineering.

A spike is exploratory engineering work that assesses a feature's feasibility: the core implementation without edge cases, polish, or error handling. You keep it simple and discard it after testing, or extend it to production.

When implementing new features using agents, I've found it very useful to ask the agent to implement it as a spike first. It keeps the code focused and easier to review. You can verify the core logic before extending it with more robust edge case handling — or discover the direction is flawed from the onset and rethink your approach with less sunk cost.
